tessera

TypeScript kernels in, WGSL out. These pages run the compiler's output on your GPU and check it against a CPU reference.

Each page verifies something different, and each is meant to be able to fail. Regenerate the shaders with npm run demo before reloading.

/matmul.html matmul, four ways
A hand-written tiled GEMM, the same kernel compiled by tessera through MLIR, and the same kernel compiled straight to WGSL — measured against each other with warm-up, repetition and interleaving.
Verifies all three agree bit-for-bit, and that the GPU contracted acc + a*b into an fma. Settles which backend to keep: the direct printer reaches the hand-written kernel where the MLIR chain costs 1.57×.
 /ragged.html ragged axes
The same matmul at 1000×750×500, where no axis divides its block. The kernel body is character-identical to the aligned one and contains no mask expression; the compiler synthesises all 12 boundary checks from the extents in the types.
Verifies 750000/750000 bit-exact, tails included — 40 rows, 46 columns, 4 deep. A wrong mask would read a neighbouring row and be obvious.
 /rowwise.html the row-wise schedule
softmax and layernorm, sharing every line of one emitter. Their accumulators, passes and store are read from the body rather than matched against a template — adding layernorm after softmax added zero emitter lines.
Verifies each twice: an invariant that needs no reference at all (softmax's rows sum to 1, layernorm's have mean 0 and variance 1), then a CPU oracle on the error scale the operations actually permit.
Reading order, if this is the first visit: matmul for what the compiler emits and how it is measured, ragged for the thing the type system is for, rowwise for whether any of it generalises.
