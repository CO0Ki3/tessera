f32 literal range — rev 3, 7 rows

If you do not see seven rows, you are looking at a cached copy.

naga (Firefox, Servo, Deno) and Tint (Chrome) draw the upper bound of a float literal in different places. naga accepts anything that rounds to a finite f32; Tint accepts only values ≤ f32::MAX. Everything between those two is accepted by one and rejected by the other — and that band contains 3.4028235e38, the decimal people write when they mean the f32 maximum.

This page cannot run naga. It only calls createShaderModule in whichever browser opens it, so it measures the browser half. The naga half is one command, run separately: 

$ cat in.wgsl
@group(0) @binding(0) var<storage, read_write> o : array<f32>;
@compute @workgroup_size(1) fn main() { o[0] = 0x1.fffffep+127; }

$ naga in.wgsl out.wgsl && grep 'o\[0\]' out.wgsl
    o[0] = 340282350000000000000000000000000000000f;

Rows 1 and 2 are that pair: row 1 is the input, row 2 is what naga turned it into. If row 1 is accepted and row 2 is rejected, the rewrite is what broke the shader. Row 2's string is pasted from the command above — it is not a spelling anyone chose. Open this in both browsers. See spike/upstream/naga-f32-literal-range.md.
